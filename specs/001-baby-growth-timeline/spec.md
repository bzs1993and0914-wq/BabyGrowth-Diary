# Feature Specification: 宝宝成长记录桌面应用

**Feature Branch**: `001-baby-growth-timeline`  
**Created**: 2026-03-21  
**Status**: Draft  
**Input**: User description: "创建一个应用宝宝成长的桌面应用，帮助我在不同阶段保存宝宝当下的照片、视频、文字等形式，存储的方式以日为最小单位，可以按照日，周，月，年，等单位查看和筛选，查看方式可以是平铺，也可以是折叠，上传的图片或视频，如果有配文，可以像日记形式展示。尽量优化数据存储的尺寸，不至于本地的SQLite 内存增长的太快，主体风格可以多样性一些，整体界面要干净整洁。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 每日记录创建 (Priority: P1)

作为新手父母，我希望能够快速为宝宝创建一条每日记录，上传照片或视频并添加文字描述，这样我就能随时捕捉宝宝的成长瞬间。

一条记录以「日」为最小存储单位。同一天可以添加多张图片、多段视频和多段文字，它们归属于同一个日期节点。创建记录的操作 MUST 简单快捷，3 次点击以内完成核心上传流程。

**Why this priority**: 这是应用的核心价值——如果不能快速创建记录，其他所有功能都没有意义。这是 MVP 的基础。

**Independent Test**: 启动应用 → 点击"添加记录" → 选择日期 → 上传一张图片并输入描述文字 → 保存成功后在当天的时间节点上能看到该记录。

**Acceptance Scenarios**:

1. **Given** 用户在应用主界面，**When** 用户点击"添加记录"按钮并选择今天的日期，**Then** 系统打开记录编辑界面，默认日期为今天
2. **Given** 记录编辑界面已打开，**When** 用户上传一张 JPEG 图片并输入"宝宝第一次微笑"作为描述，**Then** 系统保存该记录，图片被压缩生成缩略图，原图保留在本地文件系统
3. **Given** 记录编辑界面已打开，**When** 用户上传一段 MP4 视频（200MB），**Then** 系统保存视频引用路径，自动生成视频缩略图用于列表展示
4. **Given** 用户只想记录文字，**When** 用户不上传任何媒体文件，仅输入一段文字描述，**Then** 系统以纯文字日记形式保存该记录
5. **Given** 同一天已有一条记录，**When** 用户再次为同一天添加内容，**Then** 新内容追加到该日期节点下，不覆盖已有内容

---

### User Story 2 - 时间轴浏览与筛选 (Priority: P2)

作为父母，我希望能够按照不同时间粒度（日/周/月/年）浏览宝宝的成长记录，并且可以在平铺和折叠两种视图之间切换，这样我能以不同视角回顾宝宝的成长历程。

**Why this priority**: 记录的价值在于回顾。时间轴浏览是用户在创建记录之后使用最频繁的功能，直接影响应用的长期留存价值。

**Independent Test**: 创建若干跨越不同日期的记录 → 在时间轴视图中切换日/周/月/年粒度 → 验证每种粒度下记录正确聚合显示 → 切换平铺/折叠视图 → 验证展示方式变化正确。

**Acceptance Scenarios**:

1. **Given** 系统中存在跨越 30 天的记录，**When** 用户选择"月视图"，**Then** 记录按月聚合展示，显示每月的记录数量和代表性缩略图
2. **Given** 用户正在查看月视图，**When** 用户切换到"周视图"，**Then** 记录按自然周重新聚合，周一至周日为一组
3. **Given** 用户正在查看平铺模式，**When** 用户切换为"折叠模式"，**Then** 每个时间节点折叠为一行摘要（日期 + 记录数 + 首张缩略图），点击可展开查看详情
4. **Given** 用户在平铺模式下浏览，**When** 某条记录包含图片和配文，**Then** 该记录以日记形式展示：图片居中，配文在图片下方，排版清晰美观
5. **Given** 用户在年视图下，**When** 用户点击某个月份，**Then** 自动跳转到该月的月视图并展示详细记录

---

### User Story 3 - 里程碑标记 (Priority: P3)

作为父母，我希望能够将某些特殊的日期标记为里程碑（如宝宝生日、第一次翻身、第一次走路等），让这些重要时刻在时间轴上有醒目的标识，这样我在回顾时能快速找到这些珍贵时刻。

**Why this priority**: 里程碑功能增强了时间轴的信息层次，虽然不是核心创建/浏览流程的一部分，但对提升用户体验和情感价值有重要作用。

**Independent Test**: 创建一条记录 → 将该记录标记为里程碑并选择分类"身体发育 - 会翻身" → 在时间轴上验证该日期有醒目的里程碑图标 → 通过里程碑筛选功能仅查看所有里程碑记录。

**Acceptance Scenarios**:

1. **Given** 用户正在查看某天的记录，**When** 用户点击"标记为里程碑"并选择分类"身体发育 - 第一次翻身"，**Then** 该日期在时间轴上显示特殊的里程碑图标和标签
2. **Given** 系统提供预设的里程碑分类（身体发育、语言发展、情感互动、饮食变化、其他），**When** 用户选择"其他"并输入自定义名称"第一次叫妈妈"，**Then** 系统保存该自定义里程碑名称
3. **Given** 时间轴上有多个里程碑，**When** 用户启用"仅显示里程碑"筛选，**Then** 时间轴仅展示被标记为里程碑的日期，其他日期隐藏

---

### User Story 4 - 日记式展示 (Priority: P4)

作为父母，我希望当一条记录包含图片/视频和配文时，系统能以精美的日记形式展示，就像翻阅一本成长相册，这样查看记录的体验更加温馨。

**Why this priority**: 展示方式直接影响用户的情感体验。日记式排版将普通的记录提升为有温度的回忆载体，但依赖于前面的创建和浏览功能。

**Independent Test**: 创建一条包含 3 张图片和配文的记录 → 进入该记录的详情页 → 验证图文按日记形式排版：图片大图展示，配文排版在合适位置，整体风格温馨美观。

**Acceptance Scenarios**:

1. **Given** 一条记录包含 1 张图片和一段配文，**When** 用户查看该记录详情，**Then** 图片居中大图展示，配文以优雅的排版显示在图片下方，类似日记/杂志风格
2. **Given** 一条记录包含多张图片和配文，**When** 用户查看该记录详情，**Then** 图片以画廊形式排列，每张图片可单独查看配文
3. **Given** 一条记录包含视频和配文，**When** 用户查看该记录详情，**Then** 视频以内嵌播放器展示，配文在播放器下方
4. **Given** 应用提供多种主题风格，**When** 用户在设置中切换主题（如：简约白、暖阳橙、夜空蓝），**Then** 日记展示区域的配色和排版风格随之变化

---

### User Story 5 - 存储优化与数据管理 (Priority: P5)

作为用户，我希望应用能智能管理存储空间，避免数据库过快膨胀，同时让我可以导出和备份数据，这样即使长期使用也不必担心性能下降或数据丢失。

**Why this priority**: 存储优化是长期使用的保障。虽然不影响初期体验，但对于持续数月甚至数年记录宝宝成长的用户至关重要。

**Independent Test**: 上传 100 张高清图片 → 检查数据库大小未显著增长（仅存储元数据和路径）→ 检查图片缩略图已自动生成 → 执行数据导出 → 验证导出的 ZIP 包含原始文件和结构化元数据。

**Acceptance Scenarios**:

1. **Given** 用户上传一张 5MB 的原始图片，**When** 系统处理完成，**Then** 数据库中仅存储元数据（文件路径、描述、日期等），原图存储在文件系统中，同时生成一张压缩缩略图用于列表展示
2. **Given** 用户已使用应用 6 个月，积累了 500 条记录，**When** 用户查看存储统计，**Then** 系统显示数据库大小、媒体文件总大小、缩略图占用空间等明细
3. **Given** 用户希望备份所有数据，**When** 用户点击"导出数据"，**Then** 系统生成一个 ZIP 文件，包含所有原始媒体文件和一个 JSON 格式的元数据文件，可用于恢复或迁移
4. **Given** 系统检测到缩略图缓存占用超过设定阈值，**When** 系统执行清理策略，**Then** 优先清理最早的、最少访问的缩略图缓存，保留近期记录的缩略图

---

### User Story 6 - 成长曲线可视化 (Priority: P6)

作为父母，我希望能够记录宝宝的身高、体重等可量化指标，并通过趋势图直观看到宝宝的成长曲线，这样我可以了解宝宝的发育是否正常。

**Why this priority**: 成长曲线是宪法 Principle IV 的 MUST 条款。作为数据可视化功能，依赖基础记录和时间轴体系建立后再实现。

**Independent Test**: 为多个日期添加身高/体重数据 → 打开成长曲线视图 → 验证折线图正确展示趋势 → 添加新数据点后曲线实时更新。

**Acceptance Scenarios**:

1. **Given** 用户在某天的记录中，**When** 用户点击"添加成长数据"并输入身高 50cm、体重 3.5kg，**Then** 系统保存该量化指标并关联到该日期
2. **Given** 系统中有跨越 3 个月的身高和体重数据，**When** 用户打开成长曲线视图，**Then** 系统以折线图展示身高和体重的时间趋势
3. **Given** 用户正在查看成长曲线，**When** 用户点击曲线上的某个数据点，**Then** 系统高亮该点并显示具体数值和对应日期

---

### Edge Cases

- 用户上传超大视频文件（> 2GB）时如何处理？——系统 MUST 提示文件过大并建议压缩，拒绝直接存储
- 用户在同一天反复添加和删除记录时，数据库如何保持一致？——使用事务确保原子操作
- 用户在记录编辑过程中意外关闭应用，未保存的内容是否丢失？——系统 SHOULD 支持自动草稿保存
- 媒体文件被用户在文件系统中手动删除后，应用如何处理断链？——系统 MUST 检测并优雅提示"文件已移除"，不导致崩溃
- 数据库文件损坏时如何恢复？——系统 SHOULD 支持从导出的 ZIP 备份恢复
- HEIC 格式图片在 Windows 平台上如何显示？——系统 MUST 自动转换 HEIC 为 JPEG 用于显示
- 用户切换主题时，已有记录的展示效果是否即时生效？——MUST 即时切换，无需重新加载

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持以「日」为最小单位创建成长记录，每条记录关联一个日期
- **FR-002**: 系统 MUST 支持在单条记录中上传多张图片（JPEG、PNG、HEIC 格式）
- **FR-003**: 系统 MUST 支持在单条记录中上传多段视频（MP4、MOV 格式）
- **FR-004**: 系统 MUST 支持为每张图片和每段视频单独添加文字描述
- **FR-005**: 系统 MUST 支持创建纯文字记录（无媒体附件）
- **FR-006**: 系统 MUST 支持按日、周、月、年四种时间粒度浏览记录
- **FR-007**: 系统 MUST 支持平铺和折叠两种视图模式切换
- **FR-008**: 系统 MUST 在平铺模式下以日记形式展示含配文的图片/视频记录
- **FR-009**: 系统 MUST 支持将记录标记为里程碑，并选择预设分类或自定义分类
- **FR-010**: 系统 MUST 在时间轴上对里程碑记录提供醒目的视觉区分
- **FR-011**: 系统 MUST 支持按里程碑分类进行筛选
- **FR-012**: 系统 MUST 将媒体文件存储在本地文件系统中，数据库仅存储元数据和文件引用路径
- **FR-013**: 系统 MUST 为上传的图片自动生成压缩缩略图，用于列表和时间轴展示
- **FR-014**: 系统 MUST 为上传的视频自动生成封面缩略图
- **FR-015**: 系统 MUST 支持图片全屏预览和缩放
- **FR-016**: 系统 MUST 支持视频应用内播放
- **FR-017**: 系统 MUST 支持数据导出为 ZIP 格式（含原始媒体文件 + JSON 元数据）
- **FR-018**: 系统 MUST 提供存储用量统计（数据库大小、媒体文件总大小）
- **FR-019**: 系统 MUST 支持至少 3 种主题风格切换
- **FR-020**: 系统 MUST 支持深色模式
- **FR-021**: 系统 MUST 拒绝超过 2GB 的单个视频文件并提示用户
- **FR-022**: 系统 SHOULD 自动读取图片 EXIF 信息获取拍摄时间作为默认记录日期
- **FR-023**: 系统 SHOULD 支持编辑过程中的自动草稿保存
- **FR-024**: 系统 MUST 在引用的媒体文件丢失时优雅显示占位提示，不导致崩溃
- **FR-025**: 系统 MUST 支持按关键词搜索记录（匹配文字条目内容和媒体描述）
- **FR-026**: 系统 MUST 支持按日期范围筛选记录
- **FR-027**: 系统 MUST 支持记录宝宝的可量化成长指标（身高、体重等）
- **FR-028**: 系统 MUST 以折线图形式展示成长指标的时间趋势

### Key Entities

- **日期记录 (DailyRecord)**: 以日期为主键的记录容器，聚合该天所有的媒体条目和文字内容。属性包括：日期、创建时间、修改时间。是否为里程碑通过关联的 Milestone 实体判断
- **成长指标 (GrowthMetric)**: 宝宝的可量化发育数据，关联到某个日期记录。属性包括：指标类型（身高/体重/头围等）、数值、单位、记录时间
- **媒体条目 (MediaEntry)**: 单个媒体文件的引用，属于某个日期记录。属性包括：文件类型（图片/视频）、原始文件路径、缩略图路径、文字描述、排序序号、创建时间
- **文字条目 (TextEntry)**: 纯文字记录，属于某个日期记录。属性包括：文字内容、排序序号、创建时间
- **里程碑 (Milestone)**: 关联到某个日期记录的特殊标记。属性包括：分类（预设/自定义）、名称、描述
- **里程碑分类 (MilestoneCategory)**: 里程碑的分类标签。预设包括：身体发育、语言发展、情感互动、饮食变化、其他。支持用户自定义添加
- **主题 (Theme)**: 应用的视觉主题配置。属性包括：主题名称、配色方案、是否为深色模式

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开应用到完成一条包含图片和描述的记录创建，全程 MUST 在 60 秒内完成
- **SC-002**: 时间轴在包含 1000 条记录时，视图切换（日/周/月/年）响应时间 MUST 小于 1 秒
- **SC-003**: 使用 6 个月（约 500 条记录、2000 张图片）后，数据库文件大小 MUST 不超过 50MB（不含媒体文件）
- **SC-004**: 图片缩略图生成 MUST 在上传后 2 秒内完成
- **SC-005**: 应用启动到主界面可交互 MUST 在 3 秒内完成
- **SC-006**: 时间轴滚动浏览 MUST 保持流畅（无可感知的卡顿）
- **SC-007**: 数据导出功能 MUST 能在 5 分钟内完成 5GB 以内数据的打包
- **SC-008**: 主题切换 MUST 即时生效，无需重新加载页面
- **SC-009**: 界面整体视觉 MUST 保持干净整洁，信息密度适中，不出现视觉混乱
