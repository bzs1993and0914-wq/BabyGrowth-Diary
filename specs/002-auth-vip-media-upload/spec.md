# Feature Specification: 账号体系、VIP 多图与上传失败默认图

**Feature Branch**: `002-auth-vip-media-upload`  
**Created**: 2026-03-25  
**Status**: Draft  
**Input**: User description: "第一阶段的MVP结构已经开发完成，接下来计划迭代后续的开发。主要的开发内容有以下几点：1、目前上传图片，都是失败的，如果有图片上传失败，并且数据提交了，请生成一张默认图，图片内容可以是关于宝宝成长曲线的图片，作为默认图。2、增加账号注册，登录，账号密码修改等功能。3、增加用户账号等级，VIP 用户可以上传大于1 张的图，最多一次上传 9 张。上传的图片查看的时候，请根据不同图片张数，排列展示。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 可靠的照片记录与失败时的默认展示 (Priority: P1)

用户在保存成长记录时，即使所选照片因网络或服务原因未能成功保存，记录仍可成功提交；当本次保存没有任何一张可用照片时，系统在查看该条记录时展示一张与「宝宝成长曲线」主题一致的默认配图，避免空白或破损体验。

**Why this priority**: 成长记录的核心价值是「有内容可看」；上传失败若导致记录看起来「坏掉」或无法辨认，会直接损害信任与日常使用意愿。

**Independent Test**: 在「全部照片未能保存但记录已保存」的验收场景下，打开该条记录，应看到统一的默认配图与正常文案，且同样操作下结果一致。

**Acceptance Scenarios**:

1. **Given** 用户已填写记录并选择照片，**When** 所有照片上传均未成功但用户仍成功保存记录，**Then** 查看该记录时显示一张约定的默认成长曲线主题配图（而非裂图、空白或错误占位符）。
2. **Given** 用户选择多张照片，**When** 至少有一张照片上传成功并保存记录，**Then** 查看该记录时仅展示成功保存的照片，不为失败项单独插入默认图（除非产品另行约定为「每槽位一张」；本规格采用「有成功图则只展示成功图」）。
3. **Given** 用户未选择任何照片，**When** 保存一条仅含文字等信息的记录，**Then** 系统行为与现有产品约定一致；若产品要求无图时也显示默认图，则与第 1 条一致展示默认图。

---

### User Story 2 - 注册、登录与修改密码 (Priority: P2)

新用户可以通过注册创建账号；已有用户可以通过登录进入应用；登录状态下用户可以修改自己的账户密码，以保证账户安全。

**Why this priority**: 账号体系是后续多设备、等级与权限的基础；没有身份边界则无法落实 VIP 与配额。

**Independent Test**: 仅启用账号相关流程即可完成注册、登录、改密全流程验收，无需依赖 VIP 或多图上传。

**Acceptance Scenarios**:

1. **Given** 用户尚未拥有账号，**When** 其使用有效凭据完成注册，**Then** 获得可用账号并能够用同一凭据登录。
2. **Given** 用户已注册，**When** 输入正确凭据，**Then** 成功进入已授权功能（与产品当前定义的登录后范围一致）。
3. **Given** 用户已登录，**When** 其在账户安全相关入口提交当前密码与新密码并满足策略要求，**Then** 新密码生效且可用新密码登录。
4. **Given** 用户输入错误凭据或不符合规则的密码，**When** 尝试登录或修改密码，**Then** 收到明确、可理解的提示，且账户状态不被破坏。

---

### User Story 3 - VIP 多图上传与按张数排列浏览 (Priority: P3)

系统区分普通用户与 VIP 用户：普通用户单次保存记录时最多关联一张照片；VIP 用户单次最多可关联九张照片。在查看记录时，界面根据实际照片数量采用合适的排列方式展示（例如单张、两张、多张网格等），使浏览清晰美观。

**Why this priority**: 在账号体系就绪后，通过等级差异化提升付费或活跃价值，并改善多图内容的阅读体验。

**Independent Test**: 使用不同等级测试账号各保存一条含不同数量照片的记录，在查看页核对数量上限与版式是否符合规则。

**Acceptance Scenarios**:

1. **Given** 用户为普通（非 VIP）账号，**When** 保存一条成长记录，**Then** 单次最多只能成功关联一张照片（选择多张时应在保存前被限制或明确提示）。
2. **Given** 用户为 VIP 账号，**When** 保存一条成长记录，**Then** 单次最多可成功关联九张照片。
3. **Given** 一条记录中有一至九张成功保存的照片，**When** 用户打开该记录的查看界面，**Then** 布局随张数变化（例如单张突出展示、两张并排、多张小图网格等），且所有照片均可辨认、无重叠遮挡导致的不可读。

---

### Edge Cases

- 用户从普通升级为 VIP 后编辑旧记录：是否允许把单次照片数从 1 扩到多张——**默认**：允许在符合 VIP 规则的前提下补充照片，直至达到 9 张上限。
- 用户从 VIP 降级：已存在的多图记录**默认**仍展示全部已存照片，但新建或编辑时受新等级上限约束（若与商业策略冲突，以产品后续决策为准）。
- 上传过程中部分成功、部分失败：以「至少一张成功则展示成功图」为准；若业务要求每张槽位独立占位，需在实现阶段与产品对齐（本规格默认不强制每槽位默认图）。
- 弱网或中断：用户多次点击保存或重试时，不应产生重复记录或不可理解的重复照片，除非产品明确允许多版本（**默认**：一条记录对应一次用户确认的保存结果）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许新用户注册账户，并对身份凭据进行基本有效性校验。
- **FR-002**: 系统必须允许已注册用户登录，并在凭据错误时拒绝访问且给出安全、可理解的反馈。
- **FR-003**: 已登录用户必须能够修改自己的登录密码；修改成功后必须使用新密码方可登录。
- **FR-004**: 系统必须区分账户等级（至少包含普通用户与 VIP），并在上传或保存记录时执行对应的照片数量上限（普通：单次 1 张；VIP：单次最多 9 张）。
- **FR-005**: 在查看成长记录时，系统必须根据该记录中成功保存的照片数量，采用适配的版面排列展示所有照片。
- **FR-006**: 当用户保存记录后，若没有任何照片被成功存储，系统必须在查看该记录时展示一张与「宝宝成长曲线」主题一致的默认配图。
- **FR-007**: 当存在至少一张成功存储的照片时，系统必须在查看时展示这些照片，且不为「未成功的上传尝试」向用户展示损坏或无法加载的图片资源。
- **FR-008**: 系统必须在用户即将违反等级对应的照片数量规则时，通过界面限制或明确提示阻止无效提交。
- **FR-009**: 系统必须保证与账户、等级相关的敏感操作（登录、改密）在失败时不泄露账户是否存在等可被滥用的细节（采用行业通行的安全表述即可）。

### Key Entities *(include if feature involves data)*

- **用户账户**：代表使用应用的个人；包含身份凭据、认证状态及账户等级（普通 / VIP）。
- **成长记录**：代表一条时间线上的记录；可关联零至多张已存储的照片，并可在无可用照片时关联「默认展示」语义（用户可见为默认配图）。
- **照片资源**：属于某条记录的可浏览图像；有存储成功与失败之分；成功数量驱动查看页排列方式。

## Assumptions

- 账户凭据以「用户名或邮箱 + 密码」一类常见组合即可满足本阶段描述；未要求第三方社交登录。
- VIP 的获得与续期方式（例如订阅、兑换码、运营配置）属于运营与计费策略，本规格只要求产品能区分并强制执行等级对应的单次上传张数。
- 「宝宝成长曲线」默认图由产品提供统一视觉资产，风格积极、与婴幼儿成长记录场景一致。
- 密码找回（忘记密码）未在用户原文中强制要求；若仅实现「登录后修改密码」亦符合「账号密码修改」表述，找回流程可作为后续增量。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可用性测试中，新用户可在 3 分钟内独立完成注册并首次成功登录（凭据符合规则的前提下）。
- **SC-002**: 已登录用户在 2 分钟内可独立完成一次密码修改，并使用新密码成功登录（旧密码立即失效）。
- **SC-003**: 抽样测试中，普通账号在单次保存操作中无法持久化超过 1 张有效照片；VIP 账号在单次保存中可持久化 2～9 张且查看页与张数匹配的排列无遮挡、无缺失。
- **SC-004**: 在「全部照片未能保存但记录已保存」的验收场景下，样本记录在查看时均显示约定的默认成长曲线配图，且无不友好的错误占位。
- **SC-005**: 对含 1、2、5、9 张成功照片的记录各至少验收一次，查看页布局均与张数匹配且用户能识别每张图（主观可用性标准：测试人员无需说明即可辨认张数与内容）。
